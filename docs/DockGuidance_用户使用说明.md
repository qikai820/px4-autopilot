# DockGuidance 用户使用说明

本文按当前 PX4 工作树的 `cuav_7-nano_test` 固件与 `src/modules/dock_guidance` 实现编写，面向接线、参数配置、地面检查、模式使用和日志排查。控制律推导见 [控制律与软件设计](DockGuidance_控制律与软件设计.md)，MT6701 的逐步标定见 [相机角度使用说明](DockGuidance_MT6701_相机角度使用说明.md)，动态相对交会的判据见 [相对运动交会优化](DockGuidance_relative.md)。

## 1. 使用前先选工作路径

DockGuidance 注册名为 **Dock Guidance** 的 PX4 外部模式。进入模式后发布 NED 三维速度和航向设定值，由 PX4 多旋翼位置、姿态和角速度控制器执行。预置阶段可以先使用外部目标位置流，交接后的对接阶段需要持续有效的视觉与本机状态。模块运行或注册成功，不等于可以进入模式；入模前还有视觉/预置、定位和传感器健康检查。

| 场景 | 关键选择 | 所需数据 |
|---|---|---|
| 直接视觉引导，不使用外部目标预置 | `DOCK_PRE_EN=0` | 入模前已有可用的视觉引导设定值；高速接近通常还需目标相对 NED 位置 |
| 先到目标轨迹后方，再切换视觉 | `DOCK_PRE_EN=1`、`DOCK_PRE_REAR=1` | 新鲜的 `viztra_target` 位置与 NED 速度、本机有效全球参考和局部状态；到达后方参考附近且视觉稳定后交接 |
| 从当前位置方向接近目标，再切换视觉 | `DOCK_PRE_EN=1`、`DOCK_PRE_REAR=0` | 同样需要新鲜的 `viztra_target`；沿当前位置接近线向停靠参考点引导，视觉稳定后可在到达前交接 |
| 普通静态控制路径 | `DOCK_DYN_EN=0` | 视觉 LOS；距离用于允许高速接近和末段判定 |
| 静止或运动目标的三维相对交会 | `DOCK_DYN_EN=1`、`DOCK_TERM_EN=1`、`DOCK_PRED_EN=1` | 可信米制尺度：相对 NED 位置，或经标定且未裁剪的目标框宽高；仅有角度不足以确定交会距离 |
| 单轴俯仰相机，用真实角度做坐标变换 | `DOCK_CAM_SERVO=1`、`DOCK_CAM_ENC_EN=1` | 舵机输出、MT6701 的连续 I²C 数据和已标定零位；舵机仍使用视觉误差控制 |

**当前默认值需要特别核对：**`DOCK_PRE_EN=1`、`DOCK_PRE_REAR=1`、`DOCK_TERM_EN=1`、`DOCK_DYN_EN=0`、`DOCK_CAM_ENC_EN=0`。没有 `viztra_target` 时，通常先关闭预置入口；此时若视觉无效，Commander 会拒绝入模。`DOCK_TERM_EN=1` 会启用有时限的末段穿越，其超时是故障，不是对接成功。本文参数表列的是 `module.yaml` 默认值，板级 `param set-default` 和已保存参数可能覆盖它们；飞控上的 `param show` 才是实际值。

## 2. 固件、输入和输出

`boards/cuav/7-nano/test.px4board` 已编入 DockGuidance、Viztra 驱动和 MT6701 驱动，可在源码根目录构建：

```sh
make cuav_7-nano_test
```

产物为 `build/cuav_7-nano_test/cuav_7-nano_test.px4`。刷写后先确认实际固件版本和参数。`DOCK_GUIDANCE=1` 时，启动脚本在 Commander 运行后自动执行 `dock_guidance start`；`SENS_EN_VIZTRA=1` 时，传感器脚本按 `VIZTRA_CFG` 指定的串口启动 `viztra`。`SENS_EN_MT6701=1` 时，传感器脚本在外部 I²C 1 上启动 `mt6701`。两个传感器启动参数默认均为 `0`，修改后需保存并重启；`DOCK_CAM_ENC_EN` 只控制实测角用于坐标变换，不会启动驱动。

| 输入 | 用户应检查什么 |
|---|---|
| `viztra_observation` | `valid`、`timestamp_sample`、图像偏差 `offset_x/y`、目标框尺寸；扩展帧的 `relative_position_valid` 与 `relative_n/e/d_m` |
| `viztra_status` | 串口帧是否持续收到、有效视觉帧数量、校验/格式错误及连接状态 |
| `viztra_target` | 仅预置路径使用；当前实现要求目标 ID 为 1、来源组件为 25、位置和 NED 速度均有效且新鲜 |
| `vehicle_attitude`、`vehicle_angular_velocity`、`vehicle_local_position` | 机体姿态、角速度、局部位置和速度必须有效；预置还要求有效的全球坐标参考 |
| `sensor_encoder` | 启用 MT6701 后要求已标定、新鲜且角度落在相机行程内 |

主要输出为 `trajectory_setpoint`、`dock_guidance_setpoint`、`dock_guidance_prediction`、`dock_guidance_relative`、`dock_preposition_status`，以及启用舵机时的 `gimbal_controls`。`DOCK_THR>0` 时还会发布固定总油门请求，由下游角速度控制器在末级处理；这是会改变实际高度/制动响应的高级功能。

| 非 Dock 参数/设置 | 当前默认或约束 | 用途 |
|---|---|---|
| `SENS_EN_VIZTRA` | 0；改动需重启 | 是否在传感器启动阶段运行 Viztra 串口驱动 |
| `SENS_EN_MT6701` | 0；改动需重启 | 是否在外部 I²C 1 上自动启动 MT6701 驱动；不控制传感器供电。其他总线或改写后的 I²C 地址需手动启动 |
| `VIZTRA_CFG` | 启动脚本未配置时选 102 | Viztra 串口选择；须核对该编号在本机实际对应的端口 |
| `VIZTRA_TOUT` | 500 ms；改动需重启 | Viztra 驱动判定最近有效帧的时限 |
| PWM 输出功能 `421` | 由实际输出配置决定 | 将单轴相机舵机接到 `Gimbal Pitch` 功能；核对通道及物理转向 |
| `MNT_MODE_IN` | 建议 `-1` | DockGuidance 直接发布舵机命令时，避免其他 gimbal 发布者同时控制该输出 |
| `MPC_*` 速度、加速度、倾角、推力限制 | 随机型配置 | 仍会限制 Dock 命令的可执行速度和制动能力 |

Viztra 的 `timestamp_sample` 是完整串口帧接收时刻。`DOCK_CAM_DLY` 表示曝光到该时刻的延迟；机体历史和相机角度历史都按曝光时刻查询。像素模式下 `offset_x` 向右为正、`offset_y` 向上为正；`relative_n/e/d_m` 属于 NED 坐标，D 向下为正。`VIZTRA_TOUT` 是驱动状态的有效期限，`DOCK_OBS_TOUT` 是 DockGuidance 控制观测超时，两者用途不同。

## 3. 首次配置与地面检查

### 3.1 核对数据源和工作路径

先确认 Viztra 实际串口及协议，再设置 `SENS_EN_VIZTRA=1` 和相应 `VIZTRA_CFG`、保存参数并重启。不要仅凭默认串口编号推断接线。启动后执行：

```sh
param set SENS_EN_VIZTRA 1
param save
reboot
```

若所接串口不是当前 `VIZTRA_CFG` 指向的端口，应先按该板的串口映射设置 `VIZTRA_CFG`，再保存并重启。重启后检查：

```sh
viztra status
listener viztra_status -n 5
listener viztra_observation -n 5
dock_guidance status
```

若没有外部 `viztra_target` 数据，在**尚未进入 Dock 模式**时设置 `DOCK_PRE_EN=0`；此时入模检查依赖已经生成的有效视觉设定值。`viztra_observation.valid=1` 是输入条件之一，还需通过时间戳、姿态/速度和相机历史检查。若视觉一直为 `valid=0`，关闭预置不能让模式变得可进入。

```sh
param set DOCK_PRE_EN 0
param save
```

以上两行仅用于**没有外部目标流**的直接视觉路径。有新鲜外部目标流，且希望从当前位置方向接近时，使用下列配置：

```sh
param set DOCK_PRE_EN 1
param set DOCK_PRE_REAR 0
param show DOCK_PRE_DIST
param save
```

`DOCK_PRE_REAR=0` 的任意方向预置需要包含该接近线逻辑的固件。`DOCK_PRE_DIST` 默认 100 m，可按场景核对后再修改已有保存值。它是无视觉时相对目标的**水平参考间距**，不是最终对接距离。距离大于该值时，参考点位于当前位置到预测目标位置的连线上；已经在该距离内时，参考点取本机当前位置，不再主动向目标水平靠近。移动目标仍有目标速度前馈，实际刹停和间距需看本机跟踪结果。预置过程中，新鲜视觉连续满足 `DOCK_PRE_VIS_T` 即可交接，无需先到达参考点；若本机与预测目标的三维距离先进入 `DOCK_PRE_LOCK_D` 门槛，视觉未稳定锁定就故障退出，不会继续按 QGC 位置引导。

![俯视示意：0° 位于目标轨迹后方，90° 位于侧方](assets/dock_guidance/preposition_approach_angles.svg)

图中 0° 和 90° 只是说明来向的相对方位：以目标运动方向的反向为 0°，侧方为 90°。它们不是需要设置的飞控角度参数。`DOCK_PRE_REAR=0` 按本机实际位置计算接近线；目标静止且没有历史运动方向时，`DOCK_PRE_REAR=1` 也会使用本机到目标的接近线作为后方参考方向。图中虚线只示意几何方向，不代表实际飞行轨迹或视觉交接已经满足条件。

任意方向预置入模仍要求 `viztra_target` 的目标 ID 为 1、来源组件为 25、位置及 NED 速度有效且在 `DOCK_PRE_TOUT` 内，同时本机局部位置/速度和全球参考有效。视觉交接后还要按视觉路径的距离、视场与控制限制执行。地面或 HIL 验证时观察：

```sh
listener viztra_target -n 5
listener dock_preposition_status -n 5
listener viztra_observation -n 5
listener dock_guidance_setpoint -n 5
```

预置中 `dock_preposition_status.state=2` 表示跟随参考点，`state=7` 表示已到参考点等待视觉；查看 `target_valid`、`reference_valid`、`reference_reached`、`visual_wait_s`、`target_age_s`、`reference_position_ned`、`guidance_position_ned` 与 `vehicle_position_ned`。`bypass_active=1` 表示正在绕开目标或匹配目标速度。`state=4` 表示已交接，随后 `dock_guidance_setpoint.stage` 应进入 `ALIGN`。`visual_stable=0` 或 `viztra_observation.valid=0` 时不能把已入模当作已具备视觉对接条件。

```sh
param show DOCK_GUIDANCE
param show DOCK_PRE_EN
param show DOCK_PRE_REAR
param show DOCK_PRE_DIST
param show DOCK_PRE_LOCK_D
param show DOCK_PRE_TOUT
param show DOCK_DYN_EN
param show DOCK_TERM_EN
param show DOCK_CAM_SERVO
param show DOCK_CAM_ENC_EN
```

### 3.2 校准相机和确认距离

固定相机需核对 `DOCK_CAM_ROLL/PITCH/YAW` 与真实安装方向。单轴舵机需设置实际 PWM 输出为 `Gimbal Pitch (421)`，检查 `DOCK_CAM_P_MIN/MAX` 对应行程；PWM 通道反向与编码器方向是两件事。按原代码的相机角定义，机身水平时，舵机命令 0° 使镜头朝机头正前方，+90° 使镜头朝上。`DOCK_CAM_PITCH` 是初始命令角；模块默认 0° 对应朝前，MicoAir H743 Dock 的板级默认值改为 90°。CUAV 板级脚本包含 `PWM_AUX_FUNC1=421` 和 `DOCK_CAM_SERVO=1`；仍需核对实际固件参数和输出。

无编码器且相机实际行程不是默认 0°～90° 时，按 [无编码器舵机标定](DockGuidance_无编码器舵机标定.md) 测量光轴角/PWM 对应关系；`DOCK_CAM_OUT_LO/HI` 可分别设置行程两端的归一化输出，默认 `-1/+1` 保留旧映射。MicoAir H743 Dock 的 ES08MA 采用 1:1 传动，PWM5 实测端点为 90°/1500 μs 和 30°/2100 μs；启动角为 90°，软件下限为 30°。

若接入 1:1 传动的 MT6701，先在未解锁状态按 [MT6701 相机角度使用说明](DockGuidance_MT6701_相机角度使用说明.md) 启动 I²C 驱动，将相机摆到机体相对 +90° 并执行 `dock_guidance calib_90`，再核对向下转动时实测角减小、已知中间角与计数变化一致，最后启用 `DOCK_CAM_ENC_EN=1`。编码器只用于相机到机体坐标变换，不改变舵机命令。

![侧视示意：飞机水平放置时，相机光轴朝机头正前方为 0°，朝上为 +90°](assets/dock_guidance/camera_pitch_0_90.svg)

图中机体轮廓取自 `dayin.stp` 的 X–Z 侧视投影，已按实际机头方向翻转为机头向右。机身长轴水平摆放仅为说明角度基准，不表示穿越机的飞行姿态；相机安装位置和转轴仅作示意。按相机坐标定义，镜头朝机头正前方为相机角 0°，向上抬至竖直为 +90°。编码器测量的是相机相对机体的角度，因此飞行中机体俯仰后，0° 不一定对地水平。实物应在朝上的 +90° 位置执行 `dock_guidance calib_90`，并核对舵机与编码器正向。这里的 0°/90° 与前文俯视图中的目标接近来向无关。

观察 `viztra_observation.relative_position_valid`。`DOCK_LEGACY_APP=0`（默认）时，静态路径缺少有效相对 NED 位置会停留在对准阶段，不会按高速接近参数加速。`DOCK_LEGACY_APP=1` 可允许仅角度接近，但受 `DOCK_LEG_VMAX` 限制，而且没有可靠米制距离供末段控制。动态相对交会需要可信尺度和多帧相对变化率，不能从单帧目标框或仅角度推断真实三维距离。

### 3.3 入模前和入模后

1. 在地面核对目标方向、相机角、舵机行程、本机位置/速度有效性和所有实际参数；先在受控低速场景验证视觉方向与限幅，再考虑高速参数。
2. 执行 `dock_guidance status`，确认 `Dock mode: registered`、视觉状态正常、无故障锁存。若启用编码器，确认 `ready=1`、`fault=0`、样本年龄连续更新。
3. 在支持该外部模式的飞行模式界面中选择 **Dock Guidance**。模式 ID 由 Commander 注册返回，不应在脚本中写死。入模成功后 `dock_guidance status` 的 `active` 变为 `yes`；`listener dock_guidance_setpoint -n 5` 的 `valid` 和 `stage` 用于确认当前引导状态。
4. 不使用预置时，视觉先进入 `ALIGN`；目标在对准区内保持 `DOCK_ALIGN_T` 后，才可能加速。有预置时先进入 `PRE_POSITION`：`DOCK_PRE_REAR=1` 跟随轨迹后方参考点，`0` 跟随当前位置接近线上的参考点；交接后进入视觉 `ALIGN`。运行中不要临时修改预置方向、相机几何、编码器零位或动态路径开关；这些会改变参考路径或清理历史。
5. 退出或发生故障后，先看飞行模式、`fault_latched` 和日志。真实视觉故障锁存后，须由驾驶员明确切换到其他模式，才会清除再次入模的锁存；不可依靠持续保持 Dock 开关自动反复重入。

## 4. 阶段和退出语义

| `stage` | 阶段 | 对操作者的含义 |
|---:|---|---|
| 0 | `NONE` | 无有效引导设定值 |
| 1 | `ALIGN` | 低速图像/航向对准，等待稳定条件 |
| 2、3 | `ACCELERATE`、`MAX_SPEED_APPROACH` | 加速并在总速度、各轴速度、加速度和视场约束内接近 |
| 4 | `TERMINAL_BRAKE` | `DOCK_TERM_EN=0` 等路径的目标前制动阶段 |
| 5、6 | `RECOVERY`、`EMERGENCY_RECOVERY` | 软/硬视场边界或数据退化后的恢复，不表示对接完成 |
| 7 | `TERMINAL_DASH` | 已提交有界末段穿越；可能短时保持最后速度，受盲飞和总时限约束 |
| 8 | `PASS_PREDICTED` | 估计穿越目标平面，进入通过后制动；**不是接触或对接成功传感器** |
| 9、10 | `STARTUP_CLIMB`、`TRACK_CAPTURE` | 动态路径的启动高度/目标捕获阶段 |
| 11 | `PRE_POSITION` | 使用外部目标位置流预置；参考点由 `DOCK_PRE_REAR` 选择轨迹后方或当前位置接近线 |

`DOCK_TERM_EN=1` 默认允许最大速度末段流程，不按 `DOCK_STOP_DIST` 提前停车。静态与动态路径的末段判据不同：静态路径可由距离或目标框比例触发 `TERMINAL_DASH`，超时会故障；三维相对交会路径还检查可达性、误差界和冻结速度穿越预测。任何 `PASS_PREDICTED` 或最近距离数字都只是估计，当前没有物理接触确认输入。

`DOCK_EXIT_MODE=0` 选择制动后 RTL，`1` 选择 Hold；若启用 `DOCK_BRK_MODE=1` 爬升制动，正常预测通过后固定请求 Hold。正常通过后，模块要求新鲜有效的本机三维速度低于 0.5 m/s 且连续保持 0.5 s，才向 Commander 请求目标模式；爬升制动还要完成收角、停止爬升和姿态稳定。故障时 Commander 先接管，后续仍由 `DOCK_EXIT_MODE` 选择目标模式；选 Hold 也须满足停车条件后才请求 Hold。定位或速度无效时，不能把没有切到 Hold 解释为故障已经消除。

## 5. 参数速查

以下数值是模块元数据默认值。单位和允许范围以 [module.yaml](../src/modules/dock_guidance/module.yaml) 及飞控实际 `param show` 为准；板级 `set-default`、用户保存值会覆盖表中默认。相机编码器参数的范围、方向和标定步骤详见 [MT6701 专页](DockGuidance_MT6701_相机角度使用说明.md)。表中的“增大/减小”只说明该参数对**设定值、判据或上限**的直接影响；实际轨迹还受视觉有效性、状态估计、MPC/机体能力、风及下游控制器限制。先确认使用的工作路径和实际参数，再只改一类参数并对比日志中的命令与实测值。

读表时区分三种量：`viztra_target` 是外部目标的全球位置/速度，用于预置；`viztra_observation` 是视觉目标方向及可选相对距离，用于视觉引导；`vehicle_local_position` 是本机估计状态。外部目标流新鲜不代表视觉已锁定，速度上限也不代表飞机一定能达到该速度。

### 启动、外部目标与预置

| 参数 | 默认 | 影响 | 原理与调整方向 |
|---|---:|---|---|
| `DOCK_GUIDANCE` | 1 | 决定启动脚本是否自动启动模块、注册 Dock 模式。 | 只管模块启动，不会使无效视觉或外部目标变有效；改动后重启并检查 `dock_guidance status`。 |
| `DOCK_PRE_EN` | 1 | 选择入模入口：1 可凭有效外部目标进入 `PRE_POSITION`；0 需已有有效视觉设定值。 | 两条入口使用不同有效性检查；关闭预置不能绕过 `viztra_observation.valid` 和设定值检查。 |
| `DOCK_PRE_DIST` | 100 m | 决定外部目标预置的目标间距；增大使参考点更远。 | 后方模式沿目标历史轨迹向后取参考点；任意方向模式沿本机到预测目标的水平接近线取停靠点。控制器叠加目标速度前馈，并向参考点减速；它不是最终对接距离。 |
| `DOCK_PRE_LOCK_D` | 100 m | 限制只靠外部位置引导可接近目标的三维距离；0 关闭此门槛。 | 本机与预测目标的三维距离进入门槛时，视觉已连续稳定则立即交接，否则故障退出。增大可更早阻止无视觉接近；它不是水平绕行距离。 |
| `DOCK_PRE_WAIT_T` | 2 s | 已到预置参考点仍未视觉锁定时，最多等待多久。 | 到达参考点后才计时，期间继续跟随移动参考点；超时故障退出。增大只延长等待，不使无效视觉变有效。 |
| `DOCK_PRE_CLEAR_D` | 50 m | 后方预置时目标周围的最小水平绕行净空。 | 直线路径穿过净空时尝试绕行，制动距离不足或无法构造安全参考时退出。增大通常使绕行更远，也可能更早判定路径不可用。 |
| `DOCK_PRE_REAR` | 1 | 1 从目标轨迹后方接近，0 从本机当前来向接近。 | 1 需到后方参考点附近且视觉稳定才交接；0 有效目标/参考和视觉稳定即可交接，不必先到停靠点。两种模式都不能凭外部目标位置直接进入视觉引导。 |
| `DOCK_PRE_RADIUS` | 250 m | 约束预置速度轨迹的水平转弯曲率。 | 速度高于 2 m/s 时按半径限制横向加速度；增大使命令转弯更缓、绕行更宽，0 关闭此约束。实际转弯半径还取决于跟踪能力。 |
| `DOCK_PRE_YAW_R` | 30°/s | 限制预置阶段朝向预测目标的航向设定值转动速度。 | 每周期只允许设定航向变化不超过“速率×周期”；增大可更快跟随目标方位，但机体仍可能跟不上。视觉交接后改用 `DOCK_YAW_RATE`。 |
| `DOCK_PRE_ZOFF` | 0 m | 调整预置参考点相对目标的高度。 | NED 的 D 向下为正，正值使参考点在目标上方；任意方向模式进入水平停靠距离内时参考点取本机当前位置，启动爬升仍可单独改变高度。 |
| `DOCK_PRE_VIS_T` | 0.3 s | 视觉需连续有效多久才算稳定锁定。 | 新鲜且有效的视觉帧累积计时，断帧或无效会重置；增大降低瞬时误锁交接概率，也延后交接并增加触及距离/等待门槛的可能。 |
| `DOCK_PRE_TOUT` | 800 ms | 外部目标流可被视为新鲜的最长年龄。 | 比较当前时间与 `viztra_target.timestamp`；超时后预置不能继续正常引用该目标。增大容忍更多输入抖动，但也可能用更旧的位置/速度。 |
| `DOCK_PRE_PRED_T` | 1 s | 限制外部目标位置向前外推的时间跨度。 | 用目标 NED 速度乘以受限预测时间修正位置；增大可补偿更大传输延迟，也会放大速度误差。 |

### 相机、视觉与传感器

相机角度、舵机命令和编码器实测角是三种不同数据。视觉像素先依分辨率与视场换成相机视线，再按**曝光时刻**的机体姿态及相机角旋转到 NED；舵机控制只根据图像误差改变命令角。启用编码器后，坐标变换取实测角，舵机闭环本身并未改用编码器。

| 参数 | 默认 | 影响 | 原理与调整方向 |
|---|---:|---|---|
| `DOCK_CAM_DLY` | 0 ms | 改变视觉帧对应的曝光时刻。 | 从 Viztra 完整帧接收时刻减去该值，再查机体姿态、位置和相机角历史；设错会在转弯或舵机运动时制造方向误差，不是舵机机械延迟。 |
| `DOCK_OBS_TOUT` | 150 ms | 决定 Dock 控制是否接受一帧视觉观测。 | 用视觉采样时刻与当前时间比较；增大容忍帧间抖动，但允许更旧的 LOS 参与控制。`VIZTRA_TOUT` 管驱动状态，不能替代它。 |
| `DOCK_CAM_ROLL` | -90° | 决定相机坐标轴如何旋转到机体坐标。 | 是安装外参的一部分；错误会把画面左右/上下误差投到错误的机体方向，必须按实际安装标定。 |
| `DOCK_CAM_PITCH` | 0° | 固定相机的安装俯仰角，或舵机启用时的初始命令角。 | 机身水平时 0° 光轴朝前，+90° 朝上；启用有效编码器后，坐标变换的俯仰分量由实测角**替代**，不是与此值相加。 |
| `DOCK_CAM_YAW` | 0° | 决定相机相对机头的水平安装偏角。 | 与 ROLL/PITCH 一起构成相机到机体旋转；设错会造成目标方位和航向修正偏差。 |
| `DOCK_CAM_SERVO` | 0 | 开启单轴俯仰舵机命令。 | 视觉上下偏差经死区、时间常数和速率/行程限制积分为命令角，再映射到 `Gimbal Pitch (421)`；只开此项不会启动 MT6701 驱动。 |
| `DOCK_CAM_ENC_EN` | 0 | 改用 MT6701 实测角计算相机视线；传感器失效会使引导无效。 | 必须有新鲜计数及标定零位，历史角与曝光时刻对齐；不改变舵机命令的生成方式，也不会自动启动驱动。 |
| `DOCK_CAM_ENC_90` | -1 count | 指定机体相对 +90° 的原始计数基准。 | `calib_90` 在未解锁且镜头已摆至 +90° 时记录；有效时优先于旧零位，-1 表示未标定。错误基准会整体偏移测量角。 |
| `DOCK_CAM_ENC_Z` | -1 count | 保留旧版 0° 标定基准。 | `calib_zero` 在镜头朝前时记录并清除 90° 基准；已有配置可继续用。基准错误同样会影响 LOS 坐标变换。 |
| `DOCK_CAM_ENC_REV` | 0 | 决定计数增减对应的实测俯仰方向。 | 反转的是相对标定基准的角度符号；应以镜头从 +90° 向下运动时实测角变小为准。它不反转 PWM 输出。 |
| `DOCK_CAM_P_MIN/MAX` | 0/90° | 限定命令角行程，也为实测角合理性检查定界。 | 舵机命令被夹在两端；MT6701 实测角容许端点外约 5° 裕量。错误端点会截断可用视角或错误拒绝编码器。 |
| `DOCK_CAM_OUT_LO/HI` | -1/+1 | 定义低/高命令角对应的归一化 `Gimbal Pitch` 输出。 | 在角度端点之间线性插值；可用 LO>HI 表示反向，但必须按实际角度/PWM 端点标定，不能只凭 PWM 数字猜方向。 |
| `DOCK_CAM_P_RATE` | 5°/s | 限制相机命令角每秒最大变化。 | 每周期最多走“速率×周期”；增大可更快追踪目标，但可能使机械动作和测量历史更难跟上。 |
| `DOCK_CAM_P_TC` | 2 s | 决定图像俯仰误差转为舵机角速度的灵敏度。 | 误差约按时间常数折算为修正速率，再受 `DOCK_CAM_P_RATE` 限制；减小通常响应更快，也更易对图像噪声动作。 |
| `DOCK_CAM_P_DB` | 0.5° | 小俯仰误差范围内停止舵机修正。 | 误差进入死区便不积分角命令；增大可减少抖动，但留下更大的画面残余偏差。 |
| `DOCK_FILT_HZ` | 2 Hz | 控制普通阶段 LOS 平滑程度。 | 低通滤波截止频率越低，画面抖动越小、响应越慢；末段可由 `DOCK_TERM_FILT` 切换更快滤波。 |
| `DOCK_RES_X/Y` | 1920/1080 px | 决定像素偏移折算成视线角的比例。 | 像素模式按图像宽高和视场做针孔投影；分辨率与实际 Viztra 输出不一致会系统性改变估计角度。 |
| `DOCK_FOV_X/Y` | 60/45° | 决定像素到 LOS 角度及视场边界的尺度。 | 视场越大，相同像素偏移对应角度越大；错误视场同时影响对准、软/硬边界判断。 |
| `DOCK_LOS_MAX` | 89° | 超出最大离轴角的观测会被拒绝。 | 用相机视线角做有效性门槛；减小可排除画面边缘畸变，但会缩小可跟踪范围。 |
| `DOCK_REL_TOUT` | 200 ms | 限制相对 NED 位置可用于米制距离控制的年龄。 | 相对位置过期时不再按旧距离加速/判末段；增大容忍数据慢更新，也增加使用旧尺度的风险。 |

### 静态接近、视场与速度

对准与加速不是同一个判据。先让目标处于对准视场并保持 `DOCK_ALIGN_T`，随后控制器才逐步增加接近速度；目标靠近边缘会降速或转入恢复。速度、加速度和图像修正都是**命令约束**，还会被 PX4 的轴向速度、推力和姿态限制再次夹紧。

| 参数 | 默认 | 影响 | 原理与调整方向 |
|---|---:|---|---|
| `DOCK_VEL_MAX` | 15 m/s | 正常接近的三维速度预算上限。 | 接近速度与图像修正共用此预算；增大只提高允许命令，不保证实速，也不能越过 FOV、米制尺度和下游控制限制。 |
| `DOCK_ACC_MAX` | 3 m/s² | 限制接近速度命令增长速度。 | 相邻周期速度设定值按加速度上限爬升；增大使请求加速更快，但不增加机体可用推力。 |
| `DOCK_DEC_MAX` | 3 m/s² | 限制常规减速命令，并参与预置参考点的刹停预算。 | 用于速度下降斜率及基于剩余距离的可停速度计算；增大可能使控制器允许更晚减速，实际能否停住须看日志实速。 |
| `DOCK_STOP_DIST` | 2 m | 关闭末段穿越时的目标前期望停车间距。 | 有米制距离时速度包络随剩余距离收紧；`DOCK_TERM_EN=1` 的静态和动态正常接近都跳过此目标前停车包络。 |
| `DOCK_ALIGN_T` | 1 s | 目标保持对准后才允许加速的等待时间。 | 连续满足对准条件才累计计时，失准会中断；增大降低短暂居中造成的误加速，也推迟加速。 |
| `DOCK_ALIGN_SPD` | 1 m/s | `ALIGN` 阶段平移速度上限。 | 对准期间仅允许有限的平移修正；增大可能更快移向目标，也会在尚未稳定对准时产生更大位移。 |
| `DOCK_FOV_ALIGN` | 0.30 | 对准区占相机半视场的比例。 | 横纵视线偏角按各自半视场归一化后比较；增大使对准更易成立，但目标允许离中心更远。 |
| `DOCK_FOV_SOFT` | 0.65 | 触发软降速/恢复的视场比例。 | 目标偏离中心超过软边界时降低接近优先级以保住目标；减小会更早降速。 |
| `DOCK_FOV_HARD` | 0.85 | 触发硬边界保护的视场比例。 | 接近画面边缘持续超限后进入更强恢复/失效处理；减小使保护更早发生，通常应大于软边界。 |
| `DOCK_FOV_H_T` | 0.15 s | 硬边界需要持续多久才确认。 | 用连续超界时间过滤瞬时图像跳动；增大减少误触发，也延后真正越界时的保护。 |
| `DOCK_REC_T` | 1 s | 目标回到安全区域后重新对准的稳定时间。 | 恢复阶段连续保持合格视场才重新进入正常接近；增大使恢复更保守。 |
| `DOCK_IMG_P` | 0.3 1/s | 图像偏差转换为横向跟踪速度的比例增益。 | 图像指向误差越大，修正速度请求越大，再受速度上限和预算限制；增大可能更快居中，也更易抖动。 |
| `DOCK_IMG_VMAX` | 1 m/s | 图像平移修正的绝对速度上限。 | 将图像误差产生的平移速度夹紧；增大允许更强修正，但仍受 `DOCK_IMG_FRAC` 与总速度预算约束。 |
| `DOCK_IMG_FRAC` | 0.40 | 图像修正可占总速度预算的最大比例。 | 在前进与居中修正之间分配速度；增大更优先保住目标，可能减少可用于接近的速度。 |
| `DOCK_LEGACY_APP` | 0 | 允许仅有角度、没有有效相对 NED 距离的旧视觉帧接近。 | 0 时缺少米制尺度不能按高速接近逻辑加速；1 时可作受限角度接近，但不能凭角度计算真实停车/穿越距离。 |
| `DOCK_LEG_VMAX` | 5 m/s | 仅角度接近的速度上限。 | 只在允许旧帧角度接近的分支生效；增大不补足缺失的米制距离证据。 |
| `DOCK_YAW_DB` | 1° | 小水平视觉误差内不调整航向。 | 误差进入死区后停止航向修正；增大减少抖动，留下更大的水平画面偏差。 |
| `DOCK_YAW_RATE` | 10°/s | 视觉阶段航向设定值最大变化率。 | 按“速率×周期”限制目标航向变化；增大使设定值追目标更快，真实偏航仍受机体限制。 |
| `DOCK_VIS_GRACE` | 300 ms | 普通阶段视觉短时丢失的降级宽限。 | 新帧超过 `DOCK_OBS_TOUT` 后先降级，持续丢失超过宽限才使引导失效；增大允许更长盲段，也延后故障退出。末段另受 `DOCK_TERM_BLIND` 约束。 |

### 动态、预测与末段

`DOCK_DYN_EN`、`DOCK_PRED_EN`、`DOCK_TERM_EN` 同开时走三维相对交会：由本机与目标的相对位置、相对速度、估计误差及飞机响应预测能否穿过目标平面。预测通过只表示几何判据成立，并非接触确认。缺少可信米制尺度时会转入受限捕获或拒绝提交末段；不要用放宽误差阈值代替传感器标定。

| 参数 | 默认 | 影响 | 原理与调整方向 |
|---|---:|---|---|
| `DOCK_DYN_EN` | 0 | 选择米制目标估计路径。 | 与 `DOCK_TERM_EN`、`DOCK_PRED_EN` 同开时使用三维相对交会；其他组合保留目标估计跟随分支。需要有效相对 NED 位置或可信的标定目标尺寸。 |
| `DOCK_PRED_EN` | 1 | 开启三维预测偏差修正。 | 用相对运动和飞机响应推算未来交会误差；与动态末段同开时参与交会规划，关闭后不能继续已提交的捕获盲穿计划。 |
| `DOCK_PRED_TAU` | 0.5 s | 改变预测中的飞机速度响应快慢。 | 模型还显式考虑命令加速度/jerk 限制；增大表示飞机响应更慢，预测可行性与提前量随之改变。应从命令速度和实速日志辨识，不是相机延迟。 |
| `DOCK_PRED_TMAX` | 5 s | 限制三维交会向未来搜索多远。 | 超出时间窗的交会不作为当前可行解；增大可考虑更远目标，也放大远期状态不确定性。 |
| `DOCK_PRED_ANG` | 15° | 限制预测修正能偏转速度方向的角度。 | 将修正向量约束在当前接近方向附近；增大允许更强横向修正，也可能要求更激烈的轨迹。 |
| `DOCK_CAP_PRED_T` | 2 s | 限制捕获阶段预测目标平面的时间。 | 捕获证据只在有限预测窗内评估；增大允许更早规划，但目标运动误差会积累。 |
| `DOCK_PRED_CFM` | 0.2 s | 预测可捕获条件必须连续成立的时长。 | 持续满足误差与可达性要求才允许提交；增大过滤短暂乐观估计，也可能错过窗口。 |
| `DOCK_BLIND_TGO` | 0.35 s | 限制提交短时盲穿时预计距目标平面的剩余时间。 | 只有目标平面足够近且其他预测/不确定度门槛通过才允许短时保持末段命令；增大允许更早盲穿，也增加外推误差。 |
| `DOCK_TGT_W/H` | 0/0 m | 给没有有效相对位置时的目标框尺度估计提供真实投影宽/高。 | 已知物理尺寸与相机 FOV、框像素尺寸构成针孔测距；0 表示该方向没有标定尺度。尺寸填错会系统性误估距离，裁剪框也不应当作完整目标尺寸。 |
| `DOCK_SIZE_ERR` | 0.15 | 目标尺寸测距的相对系统误差下限。 | 即便框检测很稳定，几何估计仍保留至少此比例的不确定度；增大使预测通过判据更保守。 |
| `DOCK_EST_ACC` | 3 | 决定目标运动估计对加速度变化的容忍度。 | 作为过程噪声扩展未来位置/速度不确定度；增大可跟随更多机动，也会降低远期穿越把握。 |
| `DOCK_EST_VMAX` | 60 m/s | 拒绝异常目标速度估计的门槛。 | 多帧位置变化推得的速度超限时不采信；增大容忍高速目标，也增加把跳点当运动的风险。 |
| `DOCK_EST_VERR` | 3 m/s | 目标速度估计误差的有效性上限。 | 不确定度超限时目标运动估计不能支撑交会；增大更容易通过估计门槛，但降低可信度要求。 |
| `DOCK_MATCH_ERR` | 2 m/s | 旧目标跟随分支开始接近前允许的速度差。 | 先跟随目标速度，再检查相对速度误差；增大允许在速度尚未匹配时接近。 |
| `DOCK_REL_VMAX` | 10 m/s | 限制目标相对接近速度。 | 按相对运动约束闭合速度；稳定几何捕获仍可按 `DOCK_VEL_MAX` 的可行总速度预算规划，不能把二者视为同一个绝对速度上限。 |
| `DOCK_DYN_JERK` | 8 m/s³ | 限制动态/预置速度命令的加速度变化率。 | 每周期限制加速度命令增量；减小会使轨迹更平顺，也延长起速和制动响应。 |
| `DOCK_PASS_ERR` | 3 m | 允许的预测横向误差及不确定度界。 | 预计穿越点与目标平面的偏差连同估计误差一起比较；增大会放宽几何通过判据，不等于实体接触保证。 |
| `DOCK_PASS_DIST` | 2 m | 预测通过目标平面后还需超出的距离。 | 沿锁定穿越方向判断目标已落在后方，并考虑位置误差；增大使 `PASS_PREDICTED` 更晚触发。 |
| `DOCK_TERM_EN` | 1 | 启用有总时限的末段穿越。 | 开启后静态和动态正常接近均不按 `DOCK_STOP_DIST` 预先刹停，确认预测通过后才制动；超时故障退出，不算成功。 |
| `DOCK_TERM_DIST` | 0 m | 静态路径可由米制距离触发末段；0 关闭此触发项。 | 有效相对距离进入阈值且持续确认时可转 `TERMINAL_DASH`；增大使距离条件更早满足。 |
| `DOCK_TERM_SIZE` | 0.10 | 静态路径可由目标框占画面比例触发末段。 | 框尺寸比例达到阈值且持续确认时触发；减小会更早触发，但框裁剪、尺寸变化会影响该判据。 |
| `DOCK_TERM_CFM` | 0.05 s | 末段入口条件连续成立的最短时间。 | 消除单帧尺寸或距离跳变；增大降低误进入，可能缩短实际末段可用时间。 |
| `DOCK_TERM_BLIND` | 0.50 s | 末段丢失视觉后允许沿已提交命令保持的时间。 | 依观测/目标估计年龄限制盲段，仍受总时长及预测误差检查；增大延长盲飞许可，不能代替视觉有效性。 |
| `DOCK_TERM_MAX_T` | 1.5 s | `TERMINAL_DASH` 总时长上限。 | 从末段开始计时；超过立即故障，不能把超时或最近距离视为已对接。 |
| `DOCK_TERM_FILT` | 10 Hz | 末段 LOS 滤波速度。 | 临近目标时可用更高截止频率降低滤波滞后；增大也会让图像噪声更直接进入方向估计。 |
| `DOCK_START_H` | 10 m | 已起飞后动态路径初始相对爬升高度；0 关闭。 | 入模时以当前本地高度建立启动爬升目标；有可信相对交会后可边爬升边引导，不要求先停在该高度。 |
| `DOCK_CAP_VMAX` | 3 m/s | 缺少足够米制尺度/捕获证据时限制主动捕获速度；0 禁用主动捕获。 | 捕获阶段先受此速度夹紧，再等待可靠位置、尺度和相对变化率；增大可能使证据尚未充分时接近更快。 |

### 油门、通过后制动与退出

通过后和符合条件的 Dock 故障接管期间，下游位置/姿态/角速度控制器共同执行制动。`DOCK_THR`、`DOCK_BRK_THR` 和 `DOCK_BRK_TMIN` 管的是**末级归一化总油门请求/下限**，不等于单个电机 PWM 或高度保持。`DOCK_BRK_MODE=1` 的爬升制动会用可用高度换取水平减速，再提前收角并抑制垂直速度；只应在已验证高度余量、定位和推力能力的条件下使用。

| 参数 | 默认 | 影响 | 原理与调整方向 |
|---|---:|---|---|
| `DOCK_THR` | 0 | 健康 Dock 阶段的固定归一化总油门请求；0 关闭。 | 请求在电池缩放后、控制分配前作用于机体 Z 向总油门，角速度控制仍产生力矩；增大会直接改变高度和制动响应，仍受 MPC 推力上限。 |
| `DOCK_THR_RATE` | 0.2/s | 固定油门和制动油门变化的斜率上限。 | 0.2/s 表示每秒最多变化 0.2 个归一化单位；减小使切换更慢。高速 `DOCK_BRK_TMIN` 可立即抬高下限，失效/退出模式则绕过正常斜率限制。 |
| `DOCK_BRK_EN` | 1 | 启用预测通过后及经确认 Dock 故障转 RTL 的推力保持制动。 | 根据实测水平速度反向倾斜，低速逐步还给普通控制；关闭后不使用这套推力制动，视觉恢复和末段进入判据不变。 |
| `DOCK_BRK_MODE` | 0 | 0 为推力方向制动；1 为爬升制动。 | 0 朝实测水平运动反向倾斜；1 先限幅爬升消耗动能，再收角、压低垂直速度。1 的正常预测通过后请求 Hold；故障退出仍由 `DOCK_EXIT_MODE` 选择。 |
| `DOCK_CLB_P_RATE` | 30°/s | 爬升制动的倾角设定值转动速率上限。 | 限制进入拉起及回正的角度变化；减小使姿态变化更缓，也会增加收角所需时间和高度预算。仅模式 1 使用。 |
| `DOCK_CLB_TILT` | 45° | 爬升制动允许的最大倾角。 | 先由该值限幅，再受 `MPC_TILTMAX_AIR` 和推力余量限制；增大可要求更强水平制动，但不能保证机体达到。仅模式 1 使用。 |
| `DOCK_CLB_DH_MAX` | 20 m | 一次制动会话允许增加的本地高度。 | 从首次进入制动时的本地高度起算；故障交接至 RTL 不重置已用额度。控制器提前预留收角与刹住爬升的高度，实机仍可能过冲。仅模式 1 使用。 |
| `DOCK_CLB_VMAX` | 0 m/s | 爬升制动的最大爬升速度命令。 | 0 继承 `MPC_Z_VEL_MAX_UP`，非零也不能超过 MPC 上限；增大可更快用高度换减速，但消耗高度预算更快。仅模式 1 使用。 |
| `DOCK_CLB_A_UP` | 0 m/s² | 爬升速度命令向上加速的上限。 | 0 继承 `MPC_ACC_UP_MAX`；非零与 MPC 限制取较小者，`DOCK_DYN_JERK` 继续限制加速度变化。仅模式 1 使用。 |
| `DOCK_CLB_A_DN` | 0 m/s² | 提前收住爬升速度的加速度预算。 | 0 继承 `MPC_ACC_DOWN_MAX`；用于估算停车高度和速度命令斜率，增大只表示规划时假定能更快刹住垂直速度，须核对实机能力。仅模式 1 使用。 |
| `DOCK_CLB_TMAX` | 10 s | 主动爬升制动最长持续时间。 | 达到时开始收角/捕获垂直速度，不代表已经停车；增大允许更长爬升，也增加高度与时长需求。仅模式 1 使用。 |
| `DOCK_BRK_THR` | 0.35 | 制动时的归一化总油门下限。 | 与倾角补偿后的悬停油门取较高者，低速逐渐释放；增大可保留更多推力，也可能增加爬升，`MPC_THR_MAX` 仍优先。 |
| `DOCK_BRK_TMIN` | 0.70 | 高速制动时末级总油门的较高下限。 | 实测水平速度达到 `DOCK_BRK_TVEL` 即立即生效，优先于 `DOCK_THR_RATE` 的上升斜率；增大可保留推力但可能显著改变高度。爬升模式进入收角捕获时提前释放。 |
| `DOCK_BRK_TVEL` | 8 m/s | 决定高油门地板维持到何种水平速度。 | 水平实速**严格低于**此值才解除 `DOCK_BRK_TMIN`，之后恢复油门变化斜率；增大使地板更早解除。与制动倾角的 `DOCK_BRK_VEL` 不同。 |
| `DOCK_BRK_RATE` | 45°/s | 推力方向制动的倾角命令变化率上限。 | 限制反向倾斜和回正的设定值旋转速度；增大使制动姿态请求更快，MPC 倾角限制仍优先。 |
| `DOCK_BRK_VEL` | 10 m/s | 达到该水平速度时使用完整制动倾角权重。 | 低于阈值逐步减弱制动并过渡普通速度控制，约 0.5 m/s 时释放；增大使减弱过程更早开始，可减少停下后反向运动。 |
| `DOCK_REC_YAW_V` | 2 m/s | 制动期间允许恢复航向的三维速度门槛。 | 高于门槛锁住进入制动时的实测航向；低于门槛才按 `DOCK_YAW_RATE` 转向保存目标，速度再次升高则重新锁住，避免高速时边刹车边急转头。 |
| `DOCK_EXIT_MODE` | 0 | 决定停车后的目标模式：0 RTL，1 Hold。 | 预测通过后须三维实速低于 0.5 m/s 且连续 0.5 s 才请求；故障先由 Commander 接管，Hold 也待停车条件满足。定位/速度无效时仍由 Commander 失效保护决定。 |

## 6. 状态、日志与常见问题

```sh
dock_guidance status
listener dock_guidance_setpoint -n 5
listener dock_guidance_prediction -n 5
listener dock_guidance_relative -n 5
listener dock_preposition_status -n 5
listener vehicle_local_position -n 5
listener vehicle_status -n 5
```

`dock_guidance status` 给出注册、激活、视觉有效性、故障锁存、距离、FOV、速度和相机角。`dock_guidance_setpoint.valid` 是当前引导是否可用；`velocity_valid` 和 `relative_position_valid` 分别指本机速度与目标距离；`fov_ratio` 接近 1 表示目标逼近视场边缘。`camera_mount_pitch_deg` 是命令角，`sample_mount_pitch_deg` 是曝光时刻坐标变换实际使用的角；启用 MT6701 时后者来自实测角。

| 现象 | 先查什么 |
|---|---|
| 未看到 Dock Guidance 模式 | `DOCK_GUIDANCE`、`dock_guidance status` 的 `registered`、启动脚本和 Commander 状态 |
| Viztra 连接正常但 Dock 视觉无效 | `viztra_status.observation_valid`、`viztra_observation.valid`、时间戳、画面目标及 `DOCK_OBS_TOUT`；有串口帧不等于有有效观测 |
| `DOCK_PRE_EN=0` 后不能进入模式 | 看 `viztra_observation.valid` 与 `protocol_status`、`dock_guidance_setpoint.valid`；`protocol_status=0x00` 表示有效位 `0x01` 未置位，即使持续收到帧也不能生成直接视觉入口。状态位 `0x02` 置位也表示跟踪停止 |
| 使用预置仍不能进入模式 | 看 `viztra_target` 目标 ID/来源、位置和速度有效位、`DOCK_PRE_TOUT`，以及本机局部位置/速度和全球参考；再看 `fault_latched`，启用编码器时还需 `ready=1` |
| `DOCK_PRE_REAR=0` 仍飞向轨迹后方 | 核对已刷入包含当前位置接近线逻辑的固件、实际 `param show DOCK_PRE_REAR`，以及 `dock_preposition_status.reference_position_ned` |
| 停留在 `PRE_POSITION` | 看 `dock_preposition_status.target_valid/reference_valid/visual_stable/state`；目标流失效检查时效，视觉无效检查画面目标和 Viztra 锁定状态 |
| 停留在 `ALIGN` | 目标是否处在 `DOCK_FOV_ALIGN` 内且持续 `DOCK_ALIGN_T`，是否有有效相对距离；舵机是否在行程端且画面仍偏离 |
| 相机角或目标方向错误 | 安装角 `DOCK_CAM_ROLL/YAW`、编码器零位/反向、`camera_time_aligned`、`DOCK_CAM_DLY`；同时检查 PWM 反向是否只影响舵机 |
| 接近速度低于 `DOCK_VEL_MAX` | `capture_speed_limit`、`DOCK_LEG_VMAX`、目标尺度/估计、FOV、MPC 各轴速度/加速度和推力限幅；命令速度与实速分开比较 |
| 视觉丢失后退出 | 普通阶段查 `DOCK_VIS_GRACE` 和 `DOCK_OBS_TOUT`；末段另查 `DOCK_TERM_BLIND`、`DOCK_TERM_MAX_T` 和预测拒绝原因 |
| 通过后未切 Hold/RTL | 是否真的进入 `PASS_PREDICTED`、本机速度和位置是否新鲜、三维速度是否连续低于 0.5 m/s 达 0.5 s；`DOCK_BRK_MODE=1` 还需看爬升制动是否完成收角、停止爬升和姿态稳定 |

ULog 至少对照 `viztra_observation`、`viztra_status`、`dock_guidance_setpoint`、`dock_guidance_prediction`、`dock_guidance_relative`、`dock_preposition_status`、`trajectory_setpoint`、`vehicle_local_position`、`vehicle_status`；启用编码器再查 `sensor_encoder`。`sensor_encoder` 在日志配置中是可选话题，分析前先确认实际 ULog 中存在。要判断执行能力，还需比较位置控制器设定、姿态、推力和执行器输出；只看 Dock 的速度命令不足以证明飞机达到该速度。

源码构建和独立算法回归只能检查接口与局部计算。本文所列的视场、预测、油门和制动行为仍需按实际硬件接线、地面数据、HIL 与飞行日志分别验证；预测穿越与物理对接成功应分别记录。
